# Build 02 — visual and UX upgrade

This build preserves the five destinations, local SwiftData schema, rank/scoring contracts, deterministic intelligence, logging flows and Build 01.5 verification workflow.

## Screen changes

- Dashboard: real badge/ELO hero, tier lighting, next-rank bar, provisional daily delta, readiness dial, momentum sparkline and compact objective completion rings.
- Workout: training-console hero, session/set totals, muscle-focus chips, working-set/load-volume summaries and numbered set rows. Warm-ups remain labeled and excluded from working volume.
- Recovery: native front/back vector body diagram with eight selectable muscle regions. Regional values use the lowest logged muscle recovery; unlogged regions remain unknown. Group disclosures retain individual muscle detail, confidence and short estimate context.
- Progress: refined Day/Week/Month selector, composed goal ring and start/trend/target summary, compact signed momentum, measured/trend chart, badge/ledger sparkline and collapsible baseline coverage.
- Profile: initial avatar, real rank badge, level/rank/ELO identity, responsive goal grid and concise offline/privacy state.

Weak filler and future-build promises were removed. Insight and baseline detail are disclosed on demand. Provisional scoring, recovery uncertainty, unknown data, warm-ups, trend smoothing and local fallback remain explicit.

## Motion and accessibility

Key numbers count up for approximately 440 ms. Rings and bars reveal their true values on appearance. Dashboard cards enter softly. The active rank aura pulses twice and settles. Tab highlights use matched geometry and region selection uses a short spring. All custom movement honors Reduce Motion. DEBUG UI-testing mode renders settled values to keep the five existing simulator screenshot names deterministic.

Metric accessibility exposes final values independently of animation. Existing navigation/screen/demo/ELO/profile/insight identifiers are preserved. Rank artwork and recovery controls have additional stable identifiers.

## Verification

The owner artwork importer, source/project checks and Python infrastructure tests run on Windows. Real SwiftUI types, asset compilation, hosted XCTest, UI smoke and PNG capture require the existing Xcode 27 Actions job. Consult the current Actions run and its separate stage status artifacts; Windows checks are not Apple compilation evidence.

New tests cover the 18 compiled rank images, rank mapping/byte preservation, corrupt PNG rejection, fail-before-write behavior, unknown regional recovery and front/back interaction. The existing five-screen screenshot test remains intact.

The pre-upgrade Windows job ran 36 successful XCTest cases but failed because serial SwiftPM execution did not emit the requested XML. The Windows command uses the parallel XCTest runner with one worker to generate the genuine report while retaining serial execution. Empty reports still fail verification.

## Outside this build

Live rest timers, multi-exercise session expansion, catalog expansion, adaptive physiology, cloud/accounts, backup flows and final application icon remain deferred. No new data schema or network service is introduced.
