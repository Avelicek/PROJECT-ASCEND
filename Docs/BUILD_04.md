# Build 04 — daily game loop

Start/resume a focused workout from Training or a training objective. Choose, reorder or remove exercises; edit reps, external kg, warm-ups and optional RPE; complete sets individually. Duration/distance catalog modes retain their corresponding fields. Only completed sets enter session history. Finishing opens a summary; discarding requires confirmation.

An atomic Application Support JSON file holds the unfinished workout, selected exercise and wall-clock rest deadline. Production restores it after relaunch. Demo/in-memory stores are isolated. Rest supports pause/resume, skip, added time, automatic enable/disable and per-exercise preferences. Warm-ups never start automatic rest or qualify alone for training ELO/objectives.

Progression uses two recent full sessions within 42 days, at least two comparable working sets each, matched load and reasonably consistent reps. Near-maximal effort or sufficiently confident poor recovery blocks an increase. Load steps stay within 5%; bodyweight recommendations keep external load unchanged. Missing effort lowers confidence. Previous performance excludes future, quick and warm-up-only logs.

Records compare previous full working-set history. Reps compare the same external kg; estimated 1RM applies only to loaded movements with 1–12 reps. New contexts establish a baseline. Pending PRs celebrate during training and become durable SwiftData records on finish. `reps@kg` keys preserve context using the existing record field; no schema or artwork migration. Quick aggregate logs are excluded from comparable PR/progression history.

Today shows provisional ELO, grade, status, adequately supported weight momentum and the next incomplete action. Grade A requires three distinct positive scoring categories and no penalties; B is positive without penalties; C is steady/mixed; D is negative. This is a summary of scored actions, not a health score. Closed-day feedback uses the existing ledger and actual rank badges. All rank thresholds and ELO weights remain unchanged. Cross-midnight workouts qualify on completion day. Finalization remains idempotent after midnight.

Weekly recap covers the last seven local calendar days: finalized ELO/rank, workouts/distinct training days, nutrition adherence with logging coverage, supported trend/momentum, PRs, completed and recovery-protected objectives. No readiness history is fabricated. Training streak counts consecutive weeks with two distinct training days, allowing rest; nutrition/objective streaks count qualifying days; perfect days require both fuel goals and every due objective complete or protected. An unfinished today can continue yesterday's streak.

Recovery keeps Build 03 anatomy. Working sets/contributions/RPE supply load; elapsed time, sleep duration/quality, fuel and conservative tolerance adjust decay. Load and remaining fatigue are distinct. Medium confidence requires supported inputs and an established training history. Ready windows use approximate day periods; sparse input stays visibly low confidence. Poor recovery offers an explicit recovery-day/keep-objective choice; protected objectives have no missed penalty.

Dashboard, progression, recovery and recap explanations use engine facts. Optional Foundation Models can explain these facts on device, with no numerical output or unapproved actions. The deterministic fallback remains available offline. Real inference availability/performance still requires a supported owner device.

Verification: Windows can check project wiring, delimiters, infrastructure tests and artwork contracts. It cannot verify Apple compilation or simulator rendering. CI retains warnings-as-errors, complete strict concurrency, hosted XCTest, live-workout smoke coverage and all five original screenshot exports. New deterministic cases cover progression, previous lookup, PR contexts, summaries, grading/ELO, recovery exemptions, timers, DST/streaks, draft restore/write failure, discard, persistence and completion across midnight.
